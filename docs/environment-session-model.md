# 环境与会话模型

本文定义目标规格，用于迭代 2 的环境、会话和进程架构调整；不是已经实现的 API 清单。原生命令交互见[后端执行边界](adapter-model.md)，进程处置见[进程与生命周期](worker-model.md)，实施状态见 [PLAN.md](../PLAN.md)。

## 环境

环境表示执行或目标定位的上下文，可以是当前主机、远程主机或 VM 客体。本机环境可以自动提供，不要求每次调用先创建环境对象。环境管理不包含 VM 启停或快照操作。

最小信息应能回答：环境身份、当前运行实例、已知 OS/架构、可用后端，以及 PID/路径属于哪里。无法确认的信息保持未知；不预设新顶层目录、环境数据库或远端部署服务。

必须区分以下位置：

| 位置 | 含义 |
| --- | --- |
| 控制端 | 接收 AI 请求、管理关联和工作区记录的位置 |
| 后端环境 | 调试器/采集器实际运行、解析工具路径和执行命令的位置 |
| 目标环境 | 在线进程或内核实际运行的位置；原生远程调试时可与后端不同 |

Dump/回放的输入文件在后端环境解析；其来源环境属于产物来源，不表示仍连接着原系统。只有原生调试连接时，也可以描述目标而不建立完整客体执行服务。

平台观察到重启或环境替换后应更新运行实例关联，使旧进程和现场引用不再表示当前状态。快照恢复后的识别机制留给虚拟化迭代；尚未检测到变化不能等同于已证明环境未变。

## 目标

目标是进程运行实例、内核、Dump 或回放记录，必要时包含后端原生支持的多进程目标集合。在线目标身份至少关联环境运行实例，不能只有 PID；文件路径只是定位信息，不是稳定内容身份。

迭代 2 建立会话到目标的显式关联，区分文件目标与在线运行实例；完整文件身份、历史匹配与旧记录关联在迭代 6 实现。不得因尚未做哈希索引而把两个同路径文件直接认定为同一目标。

## 会话

会话是一次可操作的调试上下文，关联后端、目标和工作区。`session_id`、后端进程 PID、目标 PID 和客户端连接分别有自己的生命周期，不能互作身份标识。

- AI 客户端连接/断开会话，不意味着创建/销毁目标。
- 多个会话可引用同一离线目标，共享历史材料，各自保有线程、栈帧、回放位置和设置。
- 同一 live target 是否允许多个控制会话取决于后端；不承诺多个调试器可以同时附加。
- 若接入同一个既有调试器上下文，应明确它是共享控制上下文，不能伪装成两个相互独立的会话。
- 一个后端进程支持多少会话由其能力决定；当前一会话一 worker 可以继续作为本机 DbgEng 实现，不能成为平台永久约束。

会话关闭只结束该调试关系及其拥有的资源。目标继续、停止或退出的处置必须由后端能力和所选策略决定，不能由 close 字样推断。更换目标时必须更新目标关联并使旧现场引用失效。

## 状态分层

对外可返回紧凑状态摘要，但内部至少区分：

| 维度 | 语义示例 | 不能推断的事实 |
| --- | --- | --- |
| 会话生命周期 | 建立中、活动、关闭、失败 | 活动不等于目标运行 |
| 后端连接 | 已连接、断开、正在核对 | 断开不等于目标退出 |
| 目标执行 | 未知、运行、停止、部分停止、退出、离线 | 部分停止不等于一致快照 |
| 操作执行 | 待执行、执行中、完成、失败、取消、结果未知 | 请求返回不必然表示目标停止 |

这是语义维度，不是要求新建四套复杂状态机或固定这些枚举拼写。迭代 2 应先解除旧 `DebugSessionState` 同时承担连接、进程和执行状态的耦合；新增字段的来源和未知状态必须明确。迭代 3 再完善异步事件、等待和状态版本交互。

底层无法提供的执行状态不得根据命令名字猜测。例如执行 g 后要核对引擎状态，不能仅凭命令字符串标成 Running。保留后端原始停止原因、异常/信号信息和作用范围。

## 操作和输出

一次操作记录输入、执行上下文、状态及零个或多个输出。结果可包括文本、结构化数据和文件；异步停止、连接变化或人工操作可写入会话事件，不必虚构一条 AI 命令。

原生执行接口概念形态为 `exec(session_id, command, wait_ms)`；这只是交互目标，不是当前 RPC 名称。`wait_ms` 是调用等待预算，与命令执行期限、录制时长、取消和目标中断分别表达。

现场相关结果应附带足够上下文：目标运行实例、线程/栈帧或回放位置，以及后端可提供的状态版本。继续执行或修改现场后，旧引用不能作为当前值继续使用；部分线程运行时的读取应标明一致性边界。相关读取协议在迭代 3 实现。

长操作尽量映射到实际客户端支持的 MCP 标准机制；内部操作记录不能依赖 MCP Task 的有效期。是否可恢复执行、是否能恢复历史、是否能重新连接，是三个独立能力。

## 迭代 2 的验收场景

1. 不显式提供环境时仍可使用默认本机环境；会话能报告后端与目标各自的归属。
2. 本机 launch/attach/文件打开经新的关联模型运行，关闭与失败处置由进程所有权及策略决定。
3. 不用 worker PID 或管道名作为公共会话身份；后端断开时可表达目标状态未知，不伪报退出。
4. 两个独立本机会话的目标和状态隔离；同一文件的两次打开不自动共享当前线程/位置。
5. 契约检查能表达后端与目标位于不同环境，且不会将远端路径本地化。此项不是远端连接实测。

尚不要求：远端传输、VM 管理、SQLite、跨会话自动缓存、完整多进程调试或服务重启后恢复引擎现场。
